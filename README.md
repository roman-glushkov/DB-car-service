# AutoPro — сайт автосервиса

## 🔐 Учётные записи и права

- **Публично регистрируется только клиент.** `/client/login` → «Зарегистрироваться»;
  сервер всегда создаёт роль `client`, роль из браузерной формы не принимается.
- **Сотрудников и новых администраторов создаёт только администратор** из
  своего кабинета («Сотрудники» и «Доступы пользователей»). Все маршруты
  `/api/admin` защищены проверкой роли `admin` на сервере.
- На `/login` доступен вход клиента и отдельная ссылка «Вход для персонала»
  (`/staff/login`). Там **нет регистрации персонала**.
- `npm run create-account` работает **только один раз**, для создания самого
  первого администратора в пустой базе. Когда администратор уже есть, команда
  не добавит второго: остальные создаются в админ-панели.
- При создании нового сотрудника система выдаёт **случайный временный пароль**,
  который показывается администратору один раз после сохранения. Запишите и
  передайте его сотруднику; затем пароль можно поменять в настройках.
- Учётные записи и пароли из старых резервных копий **не меняются** при
  обновлении проекта.

### Если вместо русских статусов появились иероглифы

Это означает, что в `order_statuses.name`, возможно, попал некорректно
декодированный текст при импорте SQL. В исходном проекте названия русские,
подключение к MariaDB использует `utf8mb4`.

1. Сделайте резервную копию БД `autoservice` в DBeaver.
2. Откройте `database/fix-order-statuses.sql` в DBeaver и выполните **весь**
   скрипт (`Alt+X`) на нужном подключении. Дамп повторно не импортируйте!
3. Скрипт меняет **только текст названий** семи статусов с ID `1..7` и не
   удаляет заказы. Строки в скрипте закодированы через hex, поэтому не зависят
   от кодировки редактора. Этот скрипт рассчитан на идентификаторы из исходной
   базы 2026-09-28.
4. Проверьте `SELECT status_id, name FROM order_statuses ORDER BY status_id;`.
   Должны получиться: Принят, Диагностика, В работе, Ожидание запчастей,
   Готов, Выдан, Отменён. Перезагрузите сайт.
